## AI가 틀렸거나 직접 고친 사례

- 상황: 패링 공격 중 타격 경직만 무시하는 기능 설계
- AI 결과: 경직 원인별로 메서드를 나누는 안(`Stagger` / `StaggerByParry`)과 bool 옵션을 제안하고 구현함
- 고친 내용: 사용자가 "경직 레벨 vs 경직 저항 레벨" 비교 방식을 제안함. 메서드 하나와 데이터 값만으로 패링 · 필살기 · 경직 불가 패턴까지 처리하도록 재구현함

- 상황: 공격 루트 모션을 대상까지 다가갈 거리에 맞게 늘이는 방식(B) 시험
- AI 결과: 클립이 끝났을 때 시작 위치에서 떨어진 거리(0.79)를 기준으로 배율을 계산함. 오가는 움직임까지 최대 18배로 커져 고무줄처럼 움직임
- 고친 내용: 사용자의 로그 값으로 원인(실제로 지나간 거리 1.32 대 끝난 위치 기준 거리 0.79)을 확인함. 클립 그대로(A)도 시험한 뒤 코드 전진 유지로 결론 내고 되돌림

- 상황: 패링 예고 시간을 `_hitDelay` 로 조절하는 설계
- AI 결과: "예고 자세를 멈춰 유지하는 시간"으로 해석해 멈춤 기능을 설계 · 제안함
- 고친 내용: 사용자 의도는 "예고가 켜지는 시점 조정"이었음. 이벤트 프레임으로 같은 조정이 가능해 `_hitDelay` 를 지우고 `Telegraph` 이벤트만 쓰기로 함

- 상황: 콤보 스킬 단계 설정 정리
- AI 결과: 동작 수와 연계 수를 묶어서 질문함 ("연계 수가 동작 수보다 많으면?")
- 고친 내용: 사용자가 둘은 관계없다고 바로잡음. 필살기처럼 단계를 모두 재생하고 `Impact` 로 다음 연계를 정하는 구조로 재정의함

- 상황: 백스텝 패턴 추가
- AI 결과: 대상이 가까우면 백스텝하는 거리 필드(`_backStepTriggerDistance`)를 제안함
- 고친 내용: 사용자가 거리 유지 필드로 충분하다고 지적함. 거리 유지를 시작할 때 확률을 한 번 뽑는 방식으로 단순화함
