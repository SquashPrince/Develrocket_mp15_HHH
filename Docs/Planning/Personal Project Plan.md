## 2. AI 활용 방침

- Claude와 Codex를 최대한 활용해 결과물을 만든다.
- AI에 휘둘리지 않는다. 구현한 코드는 한 줄 한 줄 직접 이해하고 설명할 수 있어야 한다.
- 에이전트 컨텍스트(규칙 문서)는 진행하면서 계속 관리하고 나에게 맞춰 간다.
- AI 활용 경험을 기록한다. (줄어든 작업 시간, Claude · Codex 역할 분담과 사용 차이)

| 항목 | 내용 |
|---|---|
| Claude 역할 | 기획 · 방향성 정리, Codex에게 줄 작업 지시서 작성 |
| Codex 역할 | 작업 지시서에 따른 작업 수행, UI 이미지 생성 (생성 지시문은 Claude가 작성 지원) |
| 지시 전달 방식 | 직접 전달: Claude가 쓴 작업 지시서를 사용자가 확인하고 Codex에 넘긴다 |
| 발표용 기록 | 자동 호출(Claude가 Codex CLI 직접 실행) 방식도 검토했으나, 토큰 비용과 작업 이해도 문제로 직접 전달을 선택. 이 판단 과정을 기록해 발표 자료에서 참고한다 |
| 기록 소스 | 기간 중 작업한 Issue · Commit · PR · 작업 일지 · 스킬을 정리해 기록으로 사용 |
| 기록 항목 | 작업별 소요 시간 · AI 미사용 시 예상 시간 / Claude · Codex에게 맡긴 작업과 결과 / AI가 틀렸거나 직접 고친 사례 / 에이전트 규칙 문서 변경 내역과 이유 |
| 기록 위치 | 작업 일지에 짧게 기록하고, 마무리 2일에 별도 문서로 정리 |
| AI 기억 방법 | worklog 방식을 활용하되, 기존 작업 일지 규칙과 겹치지 않도록 별도 `agentlog`로 남긴다 |
| 소요 시간 측정 | 마지막 작업 시각과 현재 시각의 간격이 30분 이상이면 AI가 작업 중단 여부를 사용자에게 묻는다. Claude 토큰이 최대한 덜 드는 방식으로 구성한다. 시각 기록: Claude Code 훅(UserPromptSubmit)이 시각을 자동 기록 · 비교하고 30분 이상일 때만 한 줄 출력. 작업 내용 · 소요 시간은 Claude가 agentlog에 기록. Codex 작업은 지시서 전달 · 결과 수신 시각을 agentlog에 기록 |

## 4. 메카닉 명세

> 메카닉마다 동작 · 레퍼런스 포인트 · 완료 조건을 채운다.

| 단계 | 메카닉 | 동작 | 레퍼런스 포인트 | 완료 조건 |
|---|---|---|---|---|
| 코어 전투 | 기본 콤보 · 강공격 | 콤보 타수는 캐릭터마다 다름. 첫 캐릭터(한손검, 임시) 기준 3타. 강공격은 공격 버튼 길게 눌러 차지 | 젠존제 기본 공격 · 차지 공격 | 콤보 단계마다 입력 버퍼를 인스펙터에서 따로 설정 가능. 차지 시간이 지나면 강공격이 자동으로 나감. 차지 도중 버튼을 떼면 기본 공격 입력으로 판정. 수치는 캐릭터 파트에서 정함 |
| 코어 전투 | 스킬 (특수기) | 캐릭터마다 다름. 한손검 캐릭터 기준: 선딜 후 크게 베기. 에너지 유무에 따라 히트 수 · 위력이 달라짐 | 젠존제 특수기 · 강화 특수기 | 수치는 캐릭터 파트에서 정함 |
| 코어 전투 | 에너지 | 캐릭터별로 따로 쌓임. 공격 적중 · 시간 경과로 증가. 최대치 120 (float). 스킬마다 요구 에너지가 다름 | 젠존제 에너지 | 획득량 · 스킬별 요구량은 캐릭터 파트에서 정함 |
| 코어 전투 | 회피 · 완벽 회피 → 반격 | 공격 중 회피 캔슬 가능. 완벽 회피 성공 시 슬로모션 + 반격 입력 | 젠존제 회피 반격 | 회피 키 입력 순간부터 0.15초 안에 적 공격이 닿으면 완벽 회피. 슬로모션 실제 시간 1초 · 0.5배속 (unscaled time 사용 검토). 반격 입력은 슬로모션 1초 동안 |
| 코어 전투 | 패링 | 입력 키: C (이전 캐릭터) / Space (다음 캐릭터). 두 키는 교체 방향만 다르고 패링 동작은 같음. 코어 전투: 두 키 모두 현재 캐릭터가 자체 패링. 파티 전투: 여기에 더해 캐릭터를 교체하고 교체된 캐릭터가 패링 | 젠존제 지원 공격 | 패링 가능(노란색) 예고가 지속되는 동안 + 0.15초까지 입력 가능. 입력하면 패링 모션 1초 유지. 패링 모션 + 피격 후 밀려나는 모션 동안 들어온 패링 가능 공격은 하나의 동작에서 전부 패링. 밀려나는 도중 연속 패링 공격이 들어오면 자동으로 패링 모션으로 막고 다시 밀려나며, 패링 지속시간은 그때마다 초기화. 적 공격 모션이 끊겨도 패링 모션은 끝까지 유지. 패링 성공 시 적은 경직 + 그로기 누적 (그로기는 파티 전투) |
| 코어 전투 | 패링 추격 | 패링 이후 이어지는 반격기. 코어 전투: 1인으로 패링 → 추격. 파티 전투: 교체된 캐릭터가 패링 → 추격 | 젠존제 지원 공격 후속타 | 패링 → 밀려남(1초) 동안 키 입력이 있었으면 밀려남이 끝난 뒤 추격 공격, 없었으면 그대로 종료. 연속 패링으로 다시 패링이 시작되면 이전 입력은 사라지고, 마지막 패링의 밀려남 동안 입력했는지로만 판정. 추격 공격 중에는 무적 (일부 공격에 무적 판정을 넣는 예시). 추격 무적 중 들어온 노란 공격은 패링되지 않음 (의도한 동작, 연속 패링 패턴은 공격 간격을 1초 이내로 설계) |
| 코어 전투 | 대시 · 회피 · 대시 공격 | 같은 키 사용. 방향 입력이 있으면 입력 방향(캐릭터가 바라보는 방향)으로 대시, 없으면 바라보는 반대쪽으로 회피(백스텝). 대시 · 회피 도중 공격 입력 시 대시 공격 | 젠존제 대시 · 회피 | 대시와 회피의 무적 · 완벽 회피 판정은 동일. 회피 반격은 완벽 회피했을 때만 발동 (대시도 동일). 완벽 회피 후 슬로모션 중 공격 입력은 대시 공격보다 회피 반격이 우선 |
| 코어 전투 | 필살기 | 캐릭터별로 쌓이는 필살기 전용 게이지로 발동 (에너지와 별개). 공격 적중 · 패링 · 완벽 회피 같은 스타일리시 입력으로 증가, 감소 없음. 최대치 3000 | 젠존제 궁극기 | 필살기 컷신 · 필살기 공격 중 무적 |
| 코어 전투 | 콤보 스킬 (틀) | 코어 전투: 1인으로 발동되는 틀만 만들어 동작 확인. 숫자패드 0으로 더미 적을 그로기 상태로 만든 뒤 테스트. 파티 전투: 그로기 조건으로 바꾸고 추가 캐릭터만 발동하도록 수정 | 젠존제 연계 공격 | 발동 → 연출 → 종료 후 기본 상태(idle · 이동)로 복귀. 이전 상태로 돌아가지 않음 |
| 코어 전투 | 적 공격 예고 | 공격 직전 예고 연출. 회피만 가능한 공격(빨간색) / 패링 가능한 공격(노란색)을 색으로 구분 | 젠존제 공격 예고 섬광 | 적 설계 제약: 노란 공격 도중에는 빨간 공격 · 패링 불가 일반 공격을 넣지 않음. 넣는다면 공통 패링 지속시간(1초)이 지난 뒤에 나오도록 조정 |
| 코어 전투 | 타겟팅 | 자동 조준: 공격 사거리 안에서 카메라 중앙 레이와 가장 가까운 적. 공격 버튼을 누르면 그 적에게 자동으로 타게팅되어 다가감. 마우스 휠 클릭으로 록온 / 해제 | 젠존제 자동 조준, 데메크 록온 | 자동 조준 범위 = 록온 거리 = 공격 사거리. 록온 대상이 공격 사거리 밖으로 나가면 록온 자동 해제 |

### 캐릭터 파트

> 캐릭터별 수치 (콤보 입력 버퍼 · 차지 시간 · 스킬 히트 수 · 위력 · 요구 에너지 · 에너지 획득량 등)를 정한다.

**구현 구조**
- 플레이어: 상태 머신 / 적 · 보스: 비헤이비어 트리 (Unity Behavior)
- 플레이어 상태 머신: 혼합 방식. 상태 전이 일부는 Animator, 나머지는 C# 코드가 결정 
  - 경계 규칙: 판정과 규칙은 코드, 애니메이션의 진행과 종료 신호는 Animator
  - 예: 콤보 입력 시간 안에 눌렀는지 판정해 다음 단으로 보낼지 1단으로 되돌릴지는 코드가 결정한다

**공통 / 캐릭터별 구분**
- 공통 (동작 틀): 기본 공격 · 강공격 · 스킬 · 특수스킬 · 대시 · 대시 공격 · 회피 · 회피 반격 · 패링 · 패링 추격 · 교체 · 빠른 지원 · 콤보 스킬 · 필살기
- 캐릭터별 (내용): 각 공통 동작에서 어떤 동작을 하는지, 스킬 효과, 기본 공격 단수, 특수스킬 소모 에너지 등
- 시스템 공통 (캐릭터 차이 없음): 이동 · 완벽 회피 판정 · 슬로모션 · 입력 버퍼 · 에너지 · 피격 · 넉백 · 타겟팅 · 록온
- 용어: 특수스킬 = 에너지를 소모해 강화된 스킬. 콤보 스킬 = 그로기가 쌓였을 때 발동하는 연계 공격 (파티 전투 단계의 "그로기 → 연계 공격")

**코어 전투 단계 구현 순서** (일 단위로 나누지 않고 순서대로 진행)
1. 이동 / 달리기 · 대시 · 회피 (Input 작성 시 게임패드 입력 포함, 완료 후 조이콘 테스트)
2. 공격 없는 더미 적 · 기본 / 강공격 · 에너지 · 스킬 / 특수스킬 · 타겟팅 / 록온 · 대시 공격 / 회피 반격
3. 공격하는 더미 적 (더미 예고 포함) · 패링 · 패링 추격 · 완벽 회피 / 슬로모션 · 피격 / 넉백
4. 콤보 스킬 (틀) · 필살기
5. 일반 적 AI (비헤이비어 트리) · 보스

- 공격 없는 더미 적: 타겟팅 / 록온 · 공격 적중 (에너지 획득) 확인용
- 공격하는 더미 적: 일정 간격으로 약공격 → 강공격 → 패링 공격을 반복. 예고는 간단한 더미 예고로 만들어 둠. 5묶음에서 비헤이비어 트리 적으로 대체
- 회피 반격: 2묶음에서는 조건 없이 발동하게 만들고, 3묶음에서 완벽 회피를 구현하며 발동 조건 추가

**파티 전투 단계 캐릭터 추가**
- 최종 캐릭터 수: 3명 (첫 캐릭터 + 2명)
- 추가 방식: 애니메이션을 직접 만들지 않는다. 코어 전투에서 만든 공통 행동 규칙에 캐릭터별 애니메이션 · 수치만 교체해 넣는다. 첫 캐릭터를 잘 만들어 두면 나머지는 캐릭터별 수정만 필요하다
- 캐릭터별 교체 방법: 애니메이션은 Animator Override Controller, 수치는 ScriptableObject로 캐릭터마다 바꿔 끼운다
  - 캐릭터마다 콤보 단수가 다를 때: 기본 Animator에 콤보 상태를 최대 단수만큼 만들어 두고, 캐릭터 데이터(ScriptableObject)의 단수까지만 코드가 다음 단으로 보낸다
- 결정 시점: 추가 캐릭터 무기는 파티 전투 착수 전 (Mixamo 확인 후), 캐릭터별 수치는 개발하며 초기값 → 조정

**파티 전투 단계 구현 순서**
1. 캐릭터 추가
2. 교체 · 빠른 지원 · 지원 공격 · 그로기 / 콤보 스킬

| 콤보 스킬 | 그로기 시 슬로모션 + 캐릭터 선택 UI, 선택 입력 3초. 입력이 없으면 다음 캐릭터 콤보 자동 발동 (콤보 취소는 추가 콘텐츠 단계 검토). 콤보 시작 시 카메라 워크만 있고 컷신 없음 |
| 카메라 흔들림 | 패링 시 타격감용 흔들림만 넣는다 (Cinemachine Impulse). 다른 동작은 나중에 결정 |
