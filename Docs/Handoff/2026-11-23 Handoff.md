## 4. 환경 · 주의 사항 (Git 에 없는 것)

- **`Assets/Imports/` 는 `.meta` 만 Git 에 있다.** 실제 에셋은 PC 끼리 직접 복사한다. 금 ~ 일에 새로 추가된 팩 : `Map/Anime Tokyo`, `UI/KeyboardAndGamepadSprites_Vol1`, `VFX/` 아래 11개 팩 전부, Grruzam 팩 파일 2개, `_Old Animation Clips/Warrior/Death/Death2.fbx`. 복사할 때 `.meta` 는 덮어쓰지 않는다 (맵 텍스처 크기 설정이 `.meta` 에 있음).
- **빌드 압축 LZ4HC 는 Git 에 없다** (Library 저장). 다른 PC 에서는 `File → Build Profiles` 에서 다시 지정.
- 빌드가 Burst 단계에서 임시 파일 오류로 실패하면 PC 환경 변수 TMPDIR 을 기본 임시 폴더로 바꾼다.
- lilToon 빌드 전처리는 심볼 `LILTOON_DISABLE_ASSET_MODIFICATION` 로 꺼져 있다. 적 행동 그래프의 참조 순환 때문에 켜면 빌드 · 에디터가 멈춘다. **에디터 도구에서 SerializedProperty 를 끝까지 따라가는 코드도 같은 이유로 멈춘다** (참조형 속성은 들어가지 않게 할 것).
- 셰이더 · 머티리얼 · 이펙트 · 캐릭터 · 적을 추가하면 **셰이더 상태를 다시 기록**해야 첫 사용 끊김이 없다 (`Game/SceneLoading.md`).
- `main-dev` 로 병합하는 PR 은 Issue 를 자동으로 닫지 않는다. 병합 후 `gh issue close` 로 닫는다.
- 저장소 Label 에 `Performance` 가 없다. 성능 작업은 `Improvement` 를 쓴다.

## 6. 사용자와 일하는 규칙 (요약)

> 원본은 `CLAUDE.md` · `Docs/Claude/` 와 사용자 메모리다. 아래는 이번 기간에 자주 쓰인 것만 모았다.

- 응답은 한국어. 질문은 하나씩, 번호와 선택지로. 매 응답 끝에 단계 · 상태 표.
- 파일 수정 · 삭제 전 승인. `main`, `main-dev` 에서 Commit · Push 금지.
- Commit · Push 는 사용자가 한다. Claude 는 `/github-commit` 으로 초안만 준다. PR 은 `/github-pr`, 일지는 `/worklog`, agentlog 는 `/agentlog`, 기술 문서는 `/tech-doc`.
- 코드 수정은 Edit 도구로만. 쓰지 않는 칸 · 변수는 만들지 않는다.
- Unity 에셋 · 씬 · Prefab 작업은 사용자가 하고, Claude 는 코드 · 문서 · 이미지 정리 스크립트를 맡는다.
- Issue · PR 에는 에셋 이름 대신 역할 이름을 쓴다.
- 작성한 일지는 고치지 않는다 (이번에는 사용자 승인으로 끝에 덧붙이기만 허용).
- `[작업 시간]` 훅이 오면 그 공백이 휴식인지 물어보고 agentlog 에 반영한다.
- 다른 게임의 UI 를 그대로 따라 만들지 않는다. 화풍 특징으로 설명한다.
