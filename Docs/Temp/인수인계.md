## 4. 사용자 작업 방식 (메모리에 있던 것)

- **Commit 시점** : 브리핑 작업 순서의 각 단계가 확인을 통과할 때마다 `/github-commit` 으로 권유하고 그 단계 파일만 안내한다. `Assets/Imports/UI` · `Assets/Imports/Animations` 아래 `.meta` 변경(세션 전부터 있던 것)은 제외 권장
- **기획서는 최신화하지 않는다** : 기획과 달라진 결정은 Issue · PR · 작업 일지 · agentlog · 기술 문서의 "기존 방식과 비교" 에만 남긴다
- **Issue · PR 에는 에셋 이름을 쓰지 않는다** : "보스", "일반 적", "엘리트" 같은 역할 이름
- **다른 방식도 먼저 찾아 제안** : 메서드 · 옵션을 늘리기 전에 데이터 · 기존 값 재사용으로 풀 수 있는지 함께 제안한다
- 질문은 번호 목록 + 선택지. 사용자는 "너는 어떻게 생각해?" 를 자주 묻는다. 근거와 반대 경우를 함께 말하고 결정은 사용자에게 둔다. 과한 기능이면 솔직히 말한다
- 사용자는 Unity 에셋 · Prefab · 클립 이벤트 · 수치를 직접 한다. Claude 는 코드 · 문서 · 값 안내
- 작업 시간 훅 알림이 오면 공백이 쉬는 시간인지 묻고 agentlog 에 반영 (사용자는 Unity 작업 · 답변 작성으로 공백이 긴 경우가 많다)
- 17:30 ~ 18:00 작업 일지 훅이 오면 `/worklog` 로 먼저 일지를 권한다
- **코드 수정은 정확히 바꿀 부분만 고치는 수정 도구로** 한다. Perl 일괄 치환에서 `|` 구분 문자가 패턴과 겹쳐 파일을 두 번 망가뜨린 적이 있다 (11-17 agentlog)
- 쓰지 않는 칸 · 변수는 만들지 않는다. 데이터 칸은 실제로 쓰는 단계에서 넣는다

    - 클립 신호 : `Telegraph` · `HitStart` · `HitEnd` · `ResistEnd` · `LeapStart` · `LeapLock` · `LeapEnd`
    - 구간 판정 : 간격(간격마다 + HitEnd 순간 막타) / 횟수(시작 · 끝 포함, 마지막이 막타). 막타 반응은 한 순간 판정에 안 씀
    - 타격마다 판정, 슬로모션 중 무적 → 연타 안 반복 완벽 회피
    - 동작마다 대상 따라가기(속도 배율, 몸 반지름에서 멈춤) · 바라보기. 공격 중 이동 멈춤은 대기 모션으로 바꾸지 않음
    - 회전 속도는 공격마다, 판정 Layer 는 적 Prefab (공용 값으로 옮길지는 나중에)
- **패링 (#52)** : 플레이어는 성공 알림만, 적이 동작 설정으로 경직 / 이어가기. 이어가기는 공격을 끊지 않고 막힌 동작을 끝까지 재생
    - 패링 한 번에 노란 공격 하나, 반응(밀려남) 중 완전 무적
    - 연속 패링 패턴 : 이어가기 동작이 있는 공격 시작 때 `ParryWindow` 에 시작 · 끝 알림 → 패턴 중 대기 캐릭터 없이 누른 방향 파티원이 다시 패링 (필드에서 퇴장 중이어도), 예고 노란색
    - 예고가 뜬 순간 기준으로 패링 가능 고정, 예고 하나에 패링 하나
    - 끼어들기 `ParrySwap` : 노란 예고일 때만 교체 키를 받음 (패링 반응 동작에 켬). `Swap` 은 일반 교체 + 지원 패링 모두
    - 일반 교체 최소 간격 (공통 설정, 실제 시간). 빠른 지원 · 패링은 제외
