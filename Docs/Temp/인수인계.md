## 3. 사용자 작업 방식 (메모리에 있던 것)

- **Commit 시점** : 브리핑 작업 순서의 각 단계가 확인을 통과할 때마다 그 시점에 `/github-commit` 으로 권유하고 그 단계 파일만 안내한다. 마지막에 몰아서 안내하지 않는다
- **기획서는 최신화하지 않는다** : 기획과 달라진 결정은 Issue · PR · 작업 일지 · agentlog 에만 남긴다. 문서 반영 단계에서 기획서를 갱신 목록에 넣지 않는다 (사용자가 직접 요청한 경우만 예외)
- **에셋 이름을 쓰지 않는다** : Issue · PR 제목 · 본문은 "보스", "일반 적", "추가 캐릭터 1" 같은 역할 이름으로
- **다른 방식도 먼저 찾아 제안** : 메서드 · 옵션을 늘리는 대신 데이터 비교 · 기존 값 재사용으로 풀 수 있는지 함께 제안한다. 평소엔 직접 제안하고, 조직 지침(절대적인 답안 금지) 때문에 곤란할 때만 힌트로
- 질답은 **하나씩, 번호 목록 + 선택지**로. "확정해서 Issue 쓰기" 와 "작업하며 정하고 PR 에 기록" 중 사용자가 그때그때 고른다
- 사용자는 Unity 에셋 · Prefab · 클립 작업을 직접 한다. Claude 는 코드 · 문서 · 값 안내. **Prefab 이 실제로 저장됐는지** 커밋 전에 파일로 확인해 주면 좋다 (오늘 한 번 누락됨)
- 작업 시간 훅 알림이 오면 공백을 쉬었는지 묻고 agentlog 에 반영 (점심 등)

## 4. 구조 · 결정 요약 (코드와 기술 문서가 원본)

> 자세한 구조는 `Docs/Technical/Player/PlayerStructure.md`, `PlayerAttack.md` 를 먼저 읽는다.

- 플레이어 기능 : PlayerController(상태 전환 · 이동 · 공격 시작, 캐릭터 데이터 · 공통 설정 보유), PlayerInputReader, PlayerActionTrigger(패링 · 필살기 · 콤보 스킬 시작), PlayerStatus(체력 · 에너지 · 게이지 · 무적 · 캐릭터 시간 배율 · 히트렉), PlayerTargeting, PlayerSlowMotion, PlayerAttackJudge, PlayerAnimation(+ EventRelay), CharacterDebugger. 공통 규칙 static : TeleportManager, BodyRadius
- 데이터 : CharacterData(캐릭터별) · CommonCharacterSettings(모든 캐릭터 공통, 에셋 하나) · ActionData(+ ActionStep 동작 목록, TeleportOption 추가 옵션). 액션 에셋은 `Assets/Datas/Player/Actions/<캐릭터>/`
- 애니메이션 이벤트(Function 이름만, Object 칸 없음) : `ComboInputOpen` · `HitStart` · `HitEnd` · `ImpactEnd` · `AttackMotionEnd` · `RecoveryEnd`
    - 구간 판정 : HitStart ~ HitEnd(강타로 끝나면 ImpactEnd). 타격 시점은 동작에서 간격(끝 넘으면 패스) / 횟수(시작 · 끝 포함 균등). 구간 길이는 클립 이벤트에서 자동 계산 → 횟수 방식은 HitStart 뒤에 HitEnd · ImpactEnd 가 같은 클립에 꼭 있어야 함
    - 한 순간 판정 동작은 HitStart 한 번
    - 이벤트 에셋(Object 값) 방식은 시험 후 되돌림 — 다시 제안하지 않는다
- 히트렉 : 공격한 캐릭터만 멈춤(적은 안 멈춤), 실제 시간으로 셈, 끝나면 무조건 배율 1, 필살기 시작 시 즉시 해제. 첫 타격 반응 옵션은 구간당 첫 적중에만 경직 · 히트렉
- 슬로모션 타이머는 실제 시간. 나중에 콤보 스킬 선택 단계도 실제 시간
- 공격 정지 거리 · 순간 이동 거리 = 대상 반지름 + 캐릭터 반지름 + 공통 공격 간격(AttackableDistance)

## 5. 보류 · 나중에 다시 꺼낼 것

- **전투 구조 방향** (전투 구조 Issue 때) : 슬로모션 · 콤보 스킬 발동 판정을 캐릭터 기능이 아닌 전투 공통 규칙으로. 슬로모션 중 교체하면 슬로모션 종료, 교체로 나온 패링은 정상 속도. 콤보 발동 → 슬로모션 + 다음 / 이전 캐릭터 선택 UI → 선택한 캐릭터가 이어서. 슬로모션은 전투 단위 오브젝트(Singleton 보다 참조 전달 우선)
- **콤보 스킬 모델** : 한 번의 콤보 스킬 = 액션의 동작 목록. 연계 수는 적의 최대 연계 수(일반 1 · 엘리트 2). 다음 연계는 콤보 스킬 중 대상에게 맞은 강타로. 파티에서는 강타 순간 다음 캐릭터가 시전, 기존 캐릭터는 남은 동작 후 대기
- **파티 전투 때** : 공통 설정은 파티 기능이 캐릭터 목록과 함께 들고 각 캐릭터에 넘겨줌(지금은 Prefab 에서 연결). 실행 중 계산한 값은 SO 에 쓰지 않는다. 콤보 스킬 순간 이동 기준을 남아 있는 캐릭터 위치로
- **캐릭터 데이터 액션 묶음** : 캐릭터별 폴더로 정리하는 것으로 결정됨(에셋 묶음 · 데이터 안 묶음은 하지 않음)
- **패링 성공 그로기 값** : 액션에 칸만 있음, 적 그로기 게이지 때 사용
- **히트렉 중 피격** : 피격 상태로 넘어가도 히트렉이 끝날 때까지 모션이 멈춤 (필살기만 즉시 해제). 문제 되면 다시 검토
- **보스 완전 슈퍼아머 패턴** : 필살기로도 경직 안 되는 패턴 아이디어, 보류. 경직 레벨 · 저항 레벨 데이터만으로 되는지 질문으로 안내
- **설정 UI** : 마우스 · 스틱 X · Y 감도 옵션과 값 저장 포함 (기존 LookSensitivity 의 설정 함수 사용)
- **연출** : 필살기 · 패링 · 스킬 카메라 워킹과 Cinemachine Impulse 를 먼저, 애니메이션 컷신은 그 뒤 결정. 액션 데이터에 연출 참조를 붙일 수 있는 구조로 제안
- **CombatTest 씬** : 더 이상 확인하지 않음(옛 마커 · 오버라이드가 남아 있어도 둠). 다음 테스트는 새 씬
