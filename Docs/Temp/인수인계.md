## 3. 사용자 작업 방식 (메모리에 있던 것)

- **Commit 시점** : 브리핑 작업 순서의 각 단계가 확인을 통과할 때마다 `/github-commit` 으로 권유하고 그 단계 파일만 안내한다. 마지막에 몰아서 안내하지 않는다. `lilToonSetting.json` 은 제외 권장. **Prefab 이 실제로 저장됐는지** 커밋 전에 파일로 확인해 준다
- **기획서는 최신화하지 않는다** : 기획과 달라진 결정은 Issue · PR · 작업 일지 · agentlog 에만 남긴다 (사용자가 직접 요청한 경우만 예외)
- **Issue · PR 에는 에셋 이름을 쓰지 않는다** : "보스", "일반 적", "추가 캐릭터 1" 같은 역할 이름. (에셋 목록 문서 `Docs/Planning/Used Assets.md` 는 예외)
- **다른 방식도 먼저 찾아 제안** : 메서드 · 옵션을 늘리는 대신 데이터 비교 · 기존 값 재사용으로 풀 수 있는지 함께 제안
- **질답은 하나씩, 번호 목록 + 선택지 (추천 표시)**. 미정 사항은 "확정해서 Issue 쓰기" 와 "작업하며 정하고 PR 에 기록" 중 사용자가 고른다
- 사용자는 Unity 에셋 · Prefab · 클립 이벤트 · 수치 측정을 직접 한다. Claude 는 코드 · 문서 · 값 안내 · 데이터 일괄 수정
- 작업 시간 훅 알림이 오면 공백에 쉬었는지 묻고 agentlog 에 반영 (사용자가 Unity 작업을 오래 하는 경우가 많다)
- 사용자는 결과를 빨리 보고 싶어 한다. 승인 받은 범위의 후속 작업은 다시 묻지 않는다

## 4. 구조 · 결정 요약 (코드와 기술 문서가 원본)

> 자세한 구조는 `Docs/Technical/Player/PlayerStructure.md`, `PlayerAttack.md`, `Docs/Technical/Enemy/EnemyCommon.md` 를 먼저 읽는다.

- 캐릭터 3명 : 검방(Knight, 기본 Animator 클립 사용) · 전사(Warrior) · 격투가(Fighter). 공통 Animator(Player) + 캐릭터별 Override Controller + 캐릭터 데이터 + 캐릭터별 액션 폴더 + 캐릭터별 Prefab. 코드 수정 없이 캐릭터 추가
    - Override 는 클립 단위라 공통 Animator 의 상태에는 클립이 꼭 있어야 한다 (검방 BasicAttack 5 는 더미). 콤보 단수는 데이터 (검방 4 · 전사 3 · 격투가 5)
    - 클립 이름 규칙 `<캐릭터>_<Animator 상태>` (`Assets/Imports/Animations/_Selected Animations/<캐릭터>/<분류>/`)
- 작업용 도구 `Tools/Clip Range Editor` : 클립 Start · End 를 바꿔도 이벤트 · Curve 의 원본 프레임 위치 유지, Curve 값 곱하기
- 애니메이션 이벤트 : `ComboInputOpen` · `HitStart` · `HitEnd` · `ImpactEnd` · `AttackMotionEnd` · `RecoveryEnd`. 판정 구간 없이 `ImpactEnd` 만 오면 그 순간 강타 한 번 (이 규칙은 `PlayerAttack.md` 에 아직 안 적음)
- 적 그로기 게이지 : 공격 적중(액션 그로기 값) · 패링 성공(패링 액션 그로기 값)으로 누적, 최대치(적마다, 일반 적 500 · 보스 5000)에서 그로기. 줄지 않음, 그로기 중 누적 없음, 끝나면 0. 게이지를 채운 강타는 바로 콤보 스킬 발동
- 적이 대상 약속으로 몸 반지름(시작 시 측정) · 록온 표시 위치(`LockOnPoint` 자식 오브젝트) 를 알려준다. 체력 기능이 구현
- 디버그 기능은 판정 범위 Gizmo 만 남음. 값은 Inspector `[확인용]` 칸으로 본다 (플레이어 체력 · 에너지 · 게이지, 적 체력 · 그로기). 타격마다 나오는 로그는 모두 지웠다
- 밸런스 : 전사 기준 배율 (기사 그로기 높음 · 무난, 격투가 에너지 높음 · 필살기 · 그로기 낮음), 이후 사용자 DPS 측정으로 조정 (전사 에너지 · 필살기 ×2, 기사 필살기 ×2, 격투가 에너지 ×0.75). 캐릭터 데이터의 초당 에너지 · 패링 · 완벽 회피 게이지는 사용자가 직접 조정한 값 유지

## 5. 보류 · 나중에 다시 꺼낼 것

- **전투 구조 방향** (다음 Issue) : 슬로모션 · 콤보 스킬 발동 판정을 캐릭터 기능이 아닌 전투 공통 규칙으로. 슬로모션 중 교체하면 슬로모션 종료, 교체로 나온 패링은 정상 속도. 슬로모션은 전투 단위 오브젝트(Singleton 보다 참조 전달 우선). 공통 설정은 파티 기능이 캐릭터 목록과 함께 들고 각 캐릭터에 넘겨줌(지금은 Prefab 에서 연결). 실행 중 계산한 값은 SO 에 쓰지 않는다. 입력 기능의 "조작 중" 여부를 교체 기능이 바꾼다
- **콤보 스킬 모델** : 한 번의 콤보 스킬 = 액션의 동작 목록. 연계 수는 적의 최대 연계 수(일반 1 · 엘리트 2). 다음 연계는 콤보 스킬 중 대상에게 맞은 강타로. 파티에서는 강타 순간 다음 캐릭터가 시전, 기존 캐릭터는 남은 동작 후 대기. 순간 이동 기준을 남아 있는 캐릭터 위치로
- **그로기 시간 연장** (콤보 이어받기 Issue) : 콤보 시전 시작 1초 동안 그로기 시간 정지(최대 시간에 미포함), 특수 스킬로 증가, 기본 12초 · 최대 15초
- **데이터 의심 항목** (사용자에게 보고함, 미조치) : 격투가 특수스킬 에너지 비용 0 · 격투가 필살기 연타 구간이 간격 0.035초 + 히트렉 0.035초라 끊겨 보임(첫 타격에만 반응 · 판정 방식 조정 제안) · 패링 그로기가 적 최대치 이상이면 패링 한 번에 그로기 · 필살기 게이지 최대 3000 대비 수급 속도
- **공통 Animator 정리 방향** : 모든 클립을 더미로 두고 검방도 Override 를 쓰는 방식 검토 (미정 항목)
- **히트렉 중 피격** : 피격 상태로 넘어가도 히트렉이 끝날 때까지 모션이 멈춤 (필살기만 즉시 해제). 문제 되면 다시 검토
- **보스 완전 슈퍼아머 패턴** : 아이디어, 보류. 경직 레벨 · 저항 레벨 데이터만으로 되는지 질문으로 안내
- **설정 UI** : 마우스 · 스틱 X · Y 감도 옵션과 값 저장 포함 (기존 감도 설정 기능 사용)
- **연출** : 필살기 · 패링 · 스킬 카메라 워킹과 Cinemachine Impulse 먼저, 애니메이션 컷신은 그 뒤 결정. 액션 데이터에 연출 참조를 붙일 수 있는 구조로 제안
- **CombatTest 씬** : 더 이상 확인하지 않음. 테스트는 `CharacterTest` 씬
- 이벤트 에셋(Object 값) 방식은 시험 후 되돌림 — 다시 제안하지 않는다
